# 开发笔记：MIX 容器、INI 覆盖规则与几个引擎细节

这份笔记记录做这个工具时踩过的坑和验证过的结论，方便后来者（或未来的自己）不用再查一遍。

## 1. 只读地拿到 `rulesmo.ini`

MO 3.3.6 的规则文件在 `expandmo99.mix` 里，第 11 个条目（`id=0xE8DF0937`, `offset=2435760`, `size=2,290,353`），首行是
`;;;;;;;;;;Mental Omega 3.3.6 RULES CONTROL FILE;;;;;;;;;;`，末行 `END OF RULES FILE`。

MIX 格式（ModdingWiki）：

```
[flags: UINT32LE]        // 可选，前 2 字节为 0 才存在
[file_count: UINT16LE]
[data_size: UINT32LE]    // 常被 mod 写成假值
file_count × entry{ id: UINT32, offset: UINT32, size: UINT32 }   // offset 相对数据区
data...
```

- `flags & 0x00010000` = 尾部 SHA1；`flags & 0x00020000` = 头部/索引 Blowfish 加密（后面跟 80 字节 key 块）→ 跳过。
- **MO 的 mix 不可靠**：`data_size` 是假的（XCC 会报校验失败），并且把 `local mix database.dat` 条目写成 `size=0xFFFFFFFF`，
  所以**不能靠文件名 CRC 反查**。本工具改用「内容识别」：遍历所有条目，找 200KB~20MB、前 220 字节含
  `RULES CONTROL FILE` 或 `[General]` 的，取最长命中。

## 2. 松散文件为什么能覆盖 mix

官方中文攻略写明「把这些文件与游戏主程序 `gamemd.exe` 放在同一目录下即可生效」；`D:\MOMOD\Mental Omega cowork`
这类在用的 mod 也确实只放了松散的 `artmo.ini` / `soundmo.ini`。

所以保存策略是：把 mix 里的原版 `rulesmo.ini` **原样复制**到游戏根目录，然后就在这份副本里改，其余字节不动。
「全部还原」= 删掉这个文件。

> 早期版本试过「末尾追加 `[单位ID]` 覆盖块」，这是**错的**：引擎遇到重复的节是**整节替换**，
> 追加块里只有你改的那几个键，`Owner` / `Prerequisite` / `Image` 这些全丢了，单位在游戏里造不出来。

## 3. INI 语义（OpenTS 文档与实测一致）

- 重复的节头会**延续**已读到的节；重复的键则是**后来的值替换先前的值**。
- `;` 之后是注释，行尾注释很常见（官方 ini 里遍地都是），改键时要保留它。
- 列表节（`[VehicleTypes]` 等）条目形如 `27 = MTNK ; Allied`。
- 没有 schema，键名大小写不敏感，值基本原样存。

## 4. 数值怎么找：单位 / 武器 / 弹头 / 生成物 / 部署 / 支援技能

- 类型注册表：`[InfantryTypes]` / `[VehicleTypes]` / `[BuildingTypes]` / `[AircraftTypes]` / `[SuperWeaponTypes]`。
- 单位自带英文名：`Name=Cavalier Medium Tank`，所以我们不依赖 CSF 也能搜索与显示。
- 武器槽：`Primary` / `Secondary` / `ElitePrimary` / `EliteSecondary`；有 `IsGattling=yes` 时还有
  `Weapon2..N` / `EliteWeapon2..N`（`WeaponCount` 管数量），`Stage{N-1}` 是解锁所需击破数。
- **加特林（盖特逻辑）**：连续多段合并显示成「加特林第2–4段（210/280 击破后）」。全表 20 个。
- **发射器**：`Spawns=` 指向它生成的单位（如 `V3 → V3ROCKET`），共 18 个；`Spawner=yes` 的武器只是占位
  （`Damage=1`、`Warhead=Special3`）。真正的伤害多数走引擎内置：
  `[CombatDamage]` 里 `V3Warhead` / `V3EliteWarhead` / `DMislWarhead` 指向弹头；
  而 `V2ROCKET` / `PSBOM` / `ICBMROCKET` 另有显式 `Missile.Damage=` / `Missile.Warhead=`。
  > 实测：给 `V3ROCKET` 手工加 `Missile.Damage` 引擎不认，改弹头 `Verses` 才有效。
- **部署**：`DeploysInto=` / `UndeploysInto=` 成对出现，全表 35 个节。基地车部署后属性看的是建筑那一节。
- **支援技能**：`[SuperWeaponTypes]` 135 项，其中 94 项通过建筑的 `SuperWeapon=` / `SuperWeapon2=` / `SuperWeapons=a,b` 挂载。
  `Type` / `Action` 是引擎枚举必须配对；`SW.Damage` 只对 `GenericWarhead` 一类有效。
  空投类（`AmerParaDrop` / `UnitDelivery` / `DropPod`）送出的单位写在
  `PARADROP.TYPES`、`PARADROP.<子阵营>.TYPES`、`DELIVER.TYPES`、`DROPPOD.TYPES`；
  伞兵空降（`ParaDropSpecial`）没有 `PARADROP.TYPES`，兵种在 `[General]` 的 `AmericParaDropInf` / `AllyParaDropInf` / …
- **弹头 Verses**：11 个百分比，顺序由引擎写死：
  `none, flak, plate, light, medium, heavy, wood, steel, concrete, special_1, special_2`。改错顺序不会报错，只会伤害不对。

## 5. 科技等级：MO 与原版不一样

原版 RA2/YR 里 `TechLevel=11` 表示「需要实验室，可造」；**MO 把 11 当作不可造**（只能靠支援技能 / 渗透 / 剧情给）。
所以灰显规则的上下限是 `1..10`；另外：

- 建造场一类由基地车展开的建筑 `TechLevel=-1`，但可造，需要豁免（`deploy_pair`）。
- 16 个渗透单位（`QUICK/LIONH/CHRP/AHVYBOT2/GRUMBLE/MAMM/...`）没有 `Owner=`、没有 `Prerequisite=`
  （靠间谍渗透敌方实验室解锁），不能被「无 Owner 即不可造」判死，维护了一张 `STOLEN_TECH` 白名单。
- 「中立&其他」整栏不参与灰显：那里 1264 条里绝大多数是靠占领的科技建筑与平民，全灰了反而看不清。

## 6. 中文名是怎么对上的

官网（`mentalomega.com/ch`）的单位列表用 `<a name="mtnk"></a><b>骑士中型坦克</b>` 这种写法，锚点是**旧 RA2 单位 ID**，
和 MO 3.3.6 的节 ID 大量不一致（`GASAM→NASAM`、`YAWALL→GAFWLL`、`GAGCAN→GTGCAN`…）。
做法是四步匹配，产出 `app/data/cn_names.json`：

1. 锚点 == 节 ID；
2. 节的 `Name=` == 官网英文名；
3. 节的 `Image=` == 锚点；
4. 手工别名表（`app/data/` 里的 `merge_cn.py` 的 `ALIASES`，仓库里只留数据，脚本不保证同步）。

`cn_faction.json` 是节 ID → 阵营：官网各阵营页给四家，渗透页按「生产前提：X」判归属（**不是**「渗透敌方」那一列，那是被渗透方），
剩下靠 `Owner=` 兜底，建造场展开形态继承载体阵营。

## 7. 客户端与联机

- `Resources\ClientDefinitions.ini` 里 `ForbiddenFiles=rulesmo.ini,artmo.ini,...` 只影响联机校验。
- 实测：**只要双方 `rulesmo.ini` 字节完全一致，联机不会不同步**；版本不同步时先「重新提取」再改。
- 单机想绕开客户端的懒加载/校验，可直接 `Syringe.exe "gamemd.exe" -SPAWN -CD -SPEEDCONTROL -LOG -AFFINITY:1048575`。
  Syringe 的参数格式是 `Syringe.exe "<exe name>" <args>`，**exe 名必须带引号**，否则它直接退出。

## 8. 打包与运行时

- 用 PyInstaller（`--onefile` 与 `--onedir` 各出一份）。`app/data/art`、`cn_names.json`、`cn_faction.json` 走 `--add-data`。
- frozen 下 `sys._MEIPASS` 是只读资源目录，用户数据要放 exe 旁边的 `MOINIEditor_data\`（不可写则退到 `%LOCALAPPDATA%`）。
- **别用裁剪过的 Python 打包**：缺 `email` 会让 `importlib.metadata` 直接失败（项目自带的 `python\` 就是裁剪版）。
